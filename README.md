# SourceAnchor (소스앵커)

원자료를 수집하고, 모든 문장과 수치를 원문의 근거에 연결하는 조사·문서 작성 시스템.
이 저장소는 그중 **조사·작성 화면**(로컬 실행 시제품)이다. 전체 기획은 [docs/SOURCEANCHOR_PLAN.md](docs/SOURCEANCHOR_PLAN.md), 요구사항은 [spec/](spec/INDEX.md)에 있다.

## 실행

```
npm start          # http://localhost:8105  (PORT 로 변경)
npm test
```

Node 22 이상. 외부 패키지 의존성은 없다. 에이전트를 쓰려면 `claude`(Claude Code CLI)와 `codex`(Codex CLI)가 설치·로그인되어 있어야 한다.

처음 실행하면 `workspace/` 에 장이 없는 **빈 보고서 하나**가 만들어져 보고서 화면이 열린다. 예시·샘플 자료는 만들지 않는다.

## 화면

| 열 | 하는 일 |
|---|---|
| **상단 막대** | (장 화면) **↩ 보고서**, 장 전환(▾ 목록에서 같은 보고서의 다른 장 열기 · 삭제), **＋ 새 장**, 상태별 문장 수(누르면 해당 문장으로 이동), 실행 취소, Markdown 내보내기, **에이전트 연결**(MCP 서버·스킬·서브에이전트·anchor.md, 연결 수 표시) |
| **1 편집기** | 문장 단위 편집기. 클릭 → 작성 근거 보기, 더블클릭(Enter·F2) → 고치기, 끌기 → 옮기기·다른 열로 넘기기. `＋` 로 문장·문단 추가(새 문장은 Enter 로 이어 쓰기, Esc 로 끝). 문장을 고르고 "¶ 여기서 문단 나누기"를 누르면 그 문장부터 새 문단이 된다. ↑↓ 이동, Delete 삭제, Ctrl+Z / Ctrl+Y |
| **⚓ 작성 근거** (떠 있는 창 — "열로 넣기"로 1열과 2열 사이에 넣고 "창으로 꺼내기"로 되돌린다) | 고른 문장의 유형(사실·해석·제안·연결), 규칙 검사 상태, 수치 대조표, 계산식, 연결된 근거 카드. "원문 위치 열기"로 3열에서 해당 문장·표 셀을 강조 |
| **2 에이전트** | 모델(Fable·Opus·Codex Astra·Sol)을 골라 대화. 에이전트는 보고서를 직접 고치지 않고 **수정안**을 내며, 문장마다 ✓/✕, 문단 단위, 전체 단위로 반영·거부한다. 에이전트가 쓴 글은 제안된 제목·문단 구조대로 보이고 그대로 들어간다. 머리줄의 **분기 질문**으로 질문·답변만 따로 주고받는 창을 띄운다 |
| **3 원문** | 수집한 원문 목록과 본문. 문장·표 셀을 클릭(Ctrl·Shift 로 여러 개)해 고르고, 아래 막대의 버튼이나 끌기로 넘긴다. "＋ 원문 추가"로 Markdown·텍스트를 붙여 넣을 수 있다 |

**문장 넘기기** — 원문 문장·표 셀 → 편집기(근거가 연결된 문장으로 삽입) · 작성 근거(근거로 연결) · 채팅(메시지에 첨부). 편집기 문장 → 채팅(첨부) · 편집기 안 다른 자리(이동). 채팅의 추가 수정안 → 편집기의 원하는 자리.

**숫자** — 표와 수치 대조표는 오른쪽 정렬 + 고정폭 숫자이고, 열마다 소수 자릿수를 맞춰 소수점이 세로로 선다.

**보고서와 장** — 결과물 한 편이 **보고서**(메인문서)이고, 보고서는 **장**(하위문서)으로 이루어진다. 보고서는 목차(장의 순서·제목·지시문)만 갖고 본문은 갖지 않는다 — 실제 자료조사와 작성은 장에서 한다. 원문은 장이 소유해서 장끼리 섞이지 않고, 보고서 화면 3열에서만 전체를 읽기 전용으로 모아 본다. 장을 지우면 그 장의 원문도, 보고서를 지우면 그 장들과 원문이 모두 함께 지워진다. 마지막으로 보던 화면이 다음에 다시 열린다(주소의 `?report=M-002` · `?doc=R-002`).

**규칙 검사** — 사실·해석 문장에 인용이 있는지, 문장의 수치·단위가 연결된 근거(또는 계산식의 재계산 결과)와 일치하는지, 같은 대상·기간의 근거끼리 값이 충돌하지 않는지 본다. 통과해도 "규칙 통과"일 뿐이며, 원문과 기간·대상·조건까지 대조했다고 사람이 표시해야 "확인 완료"가 된다. 문장을 고치면 확인이 풀린다.

## 에이전트

| 선택지 | CLI | 모델 ID (환경변수로 변경) |
|---|---|---|
| Fable | `claude` | `claude-fable-5-1` (`AGENT_MODEL_FABLE`) |
| Opus | `claude` | `claude-opus-5-5` (`AGENT_MODEL_OPUS`) |
| Codex Astra | `codex` | `gpt-6-astra` (`AGENT_MODEL_ASTRA`) |
| Sol | `codex` | `gpt-5.6-sol` (`AGENT_MODEL_SOL`) |

- 각 CLI 에 로그인해 둔 계정으로 동작한다(API 키 불필요). 대화는 CLI 세션을 재개하는 방식으로 이어지고, 도중에 모델을 바꾸면 앞선 대화를 새 세션에 함께 전달한다.
- CLI 는 읽기 전용으로만 실행한다(Claude: Read·Grep·Glob 과 웹 검색·읽기 도구만, Codex: read-only 샌드박스 + 웹 검색). 파일 쓰기·명령 실행은 없다. 작업 폴더는 저장소 밖 임시 폴더다.
- **자료 조사·수집**: 문서의 원문으로 뒷받침할 수 없는 주제(새 문서는 원문이 없다)를 요청하면, 에이전트가 자료를 수집해 달라고 되묻지 않고 직접 웹을 검색해 읽고 자료를 채택한다. 채택한 URL 은 **서버가 직접 내려받아** 원본을 보관하고(`snapshots/`) 문장·표 셀 단위 원문으로 등록한 뒤, 같은 요청 안에서 에이전트가 새 원문의 위치를 근거로 수정안을 낸다. 에이전트가 옮겨 적은 글은 원문이 되지 않고, 수집되지 않은 웹 내용은 근거로 쓸 수 없다. 웹 페이지·PDF(`pdftotext` 필요 — Windows 는 Git 에 딸려 온 것을 찾는다. 위치는 페이지)·PPT(pptx — 위치는 슬라이드, 슬라이드의 표는 표 셀 단위. 예전 `.ppt` 형식은 받지 못한다)·텍스트를 받으며, http·https 공개 주소만 허용한다(이 컴퓨터·내부망 주소 거부). 받지 못한 자료는 사유가 채팅에 표시된다. 환경변수 `COLLECT_TIMEOUT_MS`, `PDFTOTEXT`.
- **채택 거부**: 원문 목록의 자료를 펼쳐(▸) "채택 거부"를 누르고 이유를 적으면 그 자료가 원문에서 빠져 거부 목록으로 간다. 에이전트는 거부 목록과 이유를 전달받아 자료 선택에 참고하고, 같은 URL 을 다시 채택해도 등록되지 않는다. 거부 목록에서 이유를 고치거나, 같은 원문 번호로 되돌리거나, 목록에서 지울 수 있다(지우면 다시 채택될 수 있다). 문장이 인용한 자료는 근거 연결을 먼저 해제해야 거부할 수 있다.
- 원문과 보고서는 프롬프트에 넣어 전달한다(원문이 12만 자를 넘으면 파일로 제공). 수정안은 서버가 앵커 존재 여부와 규칙 검사를 확인한 뒤 화면에 보내고, 검사에 걸리면 에이전트에게 한 번 되돌려 고치게 한다.
- **연결(MCP 서버·스킬)**: 상단 막대의 "에이전트 연결" 버튼에서 MCP 서버(실행 명령 또는 URL)와 스킬(SKILL.md 폴더, `~/.claude/skills`·`~/.codex/skills` 에서 찾은 목록)을 붙인다. 설정은 `workspace/agent.json` 에 저장되고, 어느 모델을 골라도 똑같이 전달된다(Claude: `--mcp-config`, Codex: `-c mcp_servers.*`). 스킬은 지침 묶음으로만 쓰인다 — 에이전트가 읽기 전용이라 스크립트 실행·파일 쓰기 단계는 수행하지 않는다.
- **서브에이전트**: "에이전트 연결"에서 이름·모델·역할 지침으로 등록한다(8개까지). 채팅에서 응답하는 에이전트가 조사 과제를 나눠 맡기며("fable 과 codex 에게 나눠 조사시켜 줘"), 독립된 과제는 동시에 돌린다. 응답 모델과 서브에이전트의 계열(Claude·Codex)이 달라도 된다 — SourceAnchor 가 띄우는 MCP 서버(`lib/subagent_mcp.js`)가 서브에이전트마다 도구 하나를 내놓고, 불리면 그 모델의 CLI 를 읽기 전용으로 한 번 실행한다. 서브에이전트는 원문(sources/*.md)과 웹만 읽고, 다른 서브에이전트를 부르지 못하며, 알려 준 내용은 원문으로 수집된 뒤에야 근거가 된다. 응답 한 번에 12회·동시 4개·과제당 6분(`SUBAGENT_TIMEOUT_MS`)까지. 부를 때마다 그 모델의 사용량이 든다.
- **anchor.md**: `workspace/anchor.md` 에 늘 지키게 할 지침(출처 기준·문체·용어)을 적어 두면 에이전트가 대화를 시작할 때 가장 먼저 받는다(서브에이전트도 받는다). "에이전트 연결" 화면에서 고치거나 파일을 직접 고친다. 대화 도중 바뀌면 다음 메시지에 다시 전달된다. 앞에서 2만 자까지 전달된다.
- **컨텍스트 사용량**: 응답이 끝날 때마다 채팅 머리줄(모델 선택 옆)에 고른 모델의 현재 컨텍스트 사용량을 `3.8k / 1.00M · 1% 미만` 처럼 표시한다. 80% 이상이면 경고색. Codex 는 세션 기록에서 읽고, 못 읽으면 `약` 을 붙인 어림값을 보인다. 서브에이전트의 사용량은 포함하지 않는다.
- **분기 질문**: 2열 머리줄의 "분기 질문"을 누르면 작성 화면 위에 별도 창이 뜬다(머리줄을 끌어 옮기고, 오른쪽 아래 모서리로 크기 조절, ✕·Esc 로 닫기 — 다시 띄우면 하던 문답이 그대로 있다). 첫 질문이 그때까지 끝난 2열 대화의 최근 문답(6건까지)을 이어받아 갈라져 나오고, 창에서 나눈 문답은 2열 대화에 남지 않는다. 질문·답변만 한다 — 수정안과 자료 수집은 2열에서 요청한다. 2열이 답하는 중에도 물을 수 있고(작업 폴더를 따로 쓴다), 한쪽을 중지해도 다른 쪽은 이어진다. "새 분기"는 문답을 비우고 지금의 2열 대화에서 다시 갈라진다. 편집기에서 고른 문장은 함께 전달되고, 답에 나온 ID 는 2열과 똑같이 그 위치를 연다.
- 환경변수: `AGENT=off`(에이전트 끄기 — 원문 검색만), `AGENT_EFFORT`(추론 강도), `AGENT_TIMEOUT_MS`(서브에이전트가 연결된 응답은 두 배), `CLAUDE_CLI` / `CODEX_CLI`(실행 파일 경로).

## 데이터

```
workspace/projects/M-001/            # 보고서(메인문서) 하나
  main.json              # 목차: 장의 순서·제목·지시문
  chapters/R-001/        # 장(하위문서) 하나 — 원문은 장끼리 함께 쓰지 않는다
    report.json          # 장: 문단 → 문장(유형, 근거 ID, 계산식) + 근거 레코드(E-0001 → 자료 버전·앵커·값/단위/기간/대상/분모)
    sources/S-001.json   # 이 장의 자료: 메타데이터(URL·발행정보·수집 시각·채택 이유) + 블록(문장·표 셀마다 고정 ID 와 페이지·슬라이드·문단 위치). 채택을 거부한 자료는 rejected { reason, at } 가 붙는다
    sources/S-001.md     # 원본과 한 쌍으로 보관하는 Markdown: 서지정보 머리말 + 본문(PDF 페이지·PPT 슬라이드 위치 표시 포함)
    snapshots/S-001.html # 에이전트가 채택해 서버가 내려받은 원본(html · pdf · pptx · txt). 붙여 넣은 원문에는 없다
workspace/workspace.json             # 마지막으로 보던 자리(보고서·장·화면)
workspace/agent.json       # 에이전트 연결 설정(MCP 서버·스킬·서브에이전트)
workspace/anchor.md        # 에이전트가 대화를 시작할 때 먼저 받는 작성자의 지침 (없어도 된다)
```

ID 체계: 보고서 `M-001` · 장 `R-001` · 자료 `S-001`(문서 안에서 매기는 번호) · 문장 `S-001.b7.s2` · 표 셀 `S-001.b7.r1c3` · 근거 `E-0001` · 보고서 문단 `P-03` · 문장 `T-0007`.

## 아직 없는 것

기획서의 단계 가운데 백그라운드 CDP 수집(스크립트로 그리는 페이지·로그인 페이지), Docling 변환(PDF 의 표 구조·좌표), 자료 묶음 내보내기(현재는 Markdown 보고서만)는 구현 전이다. 자료 검색과 원문 수집·보존은 에이전트 검색 + 서버 HTTP 내려받기로 동작하며, PDF 의 표는 구조 없이 글로만 들어온다(행·열 관계가 남지 않는다 — PPT 의 표는 파일에 구조가 있어 표 셀로 들어온다). PPT 는 슬라이드의 글상자와 표만 읽고 차트·SmartArt·발표자 노트는 읽지 않는다. 그래서 "원문 위치 열기"는 변환된 본문에서 문장·표 셀을 강조하며, PDF 페이지 이미지나 웹 스냅샷 위의 좌표 강조는 변환 단계가 위치 좌표를 제공한 뒤에 붙인다.
