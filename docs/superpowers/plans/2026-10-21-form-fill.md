# 양식 파일(docx·hwpx) 작성 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** docx·hwpx 양식을 올리면 표를 1열에 번호 붙여 그리고, 같은 에이전트가 번호로 값을 제안하며, 반영한 값을 올린 형식 그대로 내려받는다.

**Architecture:** 서버는 원본 XML 문자열 위 구간 수술(공유 스캐너 `lib/xml_spans.js` → `lib/docx_form.js`·`lib/hwpx_form.js`)과 ZIP 재작성(`lib/zip.js writeZip`)으로 읽고 쓴다. 양식은 보고서(M) 아래 독립 문서 F-번호로 `lib/forms.js` + `store.js` 블록 + `/api/books/<M>/forms` 경로(사용자 지정 문서 C-번호 선례). 에이전트는 `conv.form` 대화에서 `<form>` 을 매 턴 받고 기존 단일 펜스 안 `{"form": […]}` 로 제안하며, 화면은 네 번째 작업 화면 `#form-workspace`(1열 표 · 2열 `form_chat.js` · 3열 작성 기준·원문)다.

**Tech Stack:** Node ≥ 22.2 (ESM, 의존성 0, `node:zlib` `crc32`/`deflateRawSync`), `node --test`, 바닐라 JS 화면(`util.js h/fill`, `state.js api`).

## Global Constraints

- 파일 1,200줄 초과 금지, 900줄 권고(`test/arch.test.js` 가 1,200·최상위 import 순환 0 을 강제). 새 모듈은 위성으로, 관문의 이름은 바꾸지 않는다.
- 화면 모듈은 서로 import 하지 않는다(`forms.js`·`form_chat.js` 는 `book.js`·`documents.js`·`custom_docs.js` 를 import 하지 않는다). 진입점은 `app.js` 가 값으로 넘긴다. `explorer.js` 는 화면 모듈을 import 하지 않는다.
- 상태를 바꾸는 요청은 같은 출처 `application/json` 만. 파일은 base64 JSON `{ fileName, data }`, 본문 한도 `GUIDE_BODY_LIMIT`(8 MiB), 파일 5 MiB.
- XML 은 `parseHtml` 트리로 다시 직렬화하지 않는다. 읽기·쓰기 모두 같은 스캐너의 구간을 쓴다.
- 한도: 셀 5,000개, 값 20,000자, 지침 4,000자, 제목 200자.
- 값 규칙: 값 목록에 없는 셀 = 원본 그대로(바이트 보존), 값 == 원본 글이면 목록에서 뺀다, `""` = 빈 문단 하나.
- 번호: 섹션 → 최상위 표 → 행 → 칸 순으로 1부터. docx `<w:vMerge/>`(값 없음) 이어짐 칸은 번호 없음·그리지 않음. 잠김 = docx 칸 최상위(문단 밖) `<w:tbl`·`<w:sdt`, hwpx 중첩 `tbl`.
- 에이전트 블록은 기존 ```` ```sourceanchor ```` 펜스 하나 안. 앵커는 `R-xxx/S-xxx.bN.sN` 한정 표기. 양식 대화는 collect 없음.
- 커밋: 태스크가 리뷰를 통과하면 **그 태스크가 만들거나 고친 파일만** `git add <경로>` 해 master 에 커밋한다(사용자 확정 2026-10-21). `git add -A`·`git commit -a` 금지, 푸시 금지. 다른 세션이 같은 날 `agent.js`·`book.js`·`book_guides.js`·`capture.js`·`index.html`·`app.js`·`style.css`·`spec/*` 를 고쳐 둔 미커밋 변경이 같은 트리에 있다 — 그 파일을 고치는 태스크는 **고치기 전에 수정 시각을 확인하고 다시 읽고**, 커밋할 때 그 파일에 든 남의 변경까지 함께 커밋되는 것을 받아들인다(되돌리지 않는다).
- 8105 서버는 건드리지 않는다. 화면 확인은 복사본 작업공간 + 다른 포트 + 헤드리스 Edge(메모리 규칙).
- 모든 테스트는 `npm test` 로 통과해야 한다(기존 테스트 포함).

```js
// 빈 ZIP(EOCD 22B) → writeZip 으로 세 항목 만들기 → readZip 으로 읽기 → 한 항목 교체 → 나머지 바이트 동일·CRC 일치·mimetype 선두 저장
import assert from 'node:assert/strict';
import test from 'node:test';
import zlib from 'node:zlib';
import { readZip, writeZip } from '../lib/zip.js';

const emptyZip = () => { const b = Buffer.alloc(22); b.writeUInt32LE(0x06054b50, 0); return b; };

test('writeZip: 만들기·교체·복사 보존', () => {
  const original = writeZip(emptyZip(), { mimetype: 'application/hwp+zip', 'Contents/section0.xml': '<a>old</a>', 'Contents/header.xml': '<h/>'.repeat(50) });
  const z1 = readZip(original);
  assert.deepEqual(z1.names, ['mimetype', 'Contents/section0.xml', 'Contents/header.xml']);
  assert.equal(original.readUInt16LE(8), 0); // 첫 항목(mimetype) 저장
  assert.equal(original.toString('utf8', 30, 38), 'mimetype');
  const out = writeZip(original, { 'Contents/section0.xml': '<a>NEW 값 &amp; 한글</a>' });
  const z2 = readZip(out);
  assert.deepEqual(z2.names, z1.names);
  assert.equal(z2.read('Contents/section0.xml').toString(), '<a>NEW 값 &amp; 한글</a>');
  assert.ok(z2.read('Contents/header.xml').equals(z1.read('Contents/header.xml')));
  assert.equal(z2.read('mimetype').toString(), 'application/hwp+zip');
  // 중앙 디렉터리의 CRC 가 실제 내용의 crc32 와 같다 (Word·한글은 CRC 를 검사한다)
  const dirAt = out.readUInt32LE(out.length - 22 + 16);
  const crcOfSecond = out.readUInt32LE(dirAt + 46 + 'mimetype'.length + 16);
  assert.equal(crcOfSecond, zlib.crc32(Buffer.from('<a>NEW 값 &amp; 한글</a>')));
});

test('writeZip: 암호화 항목은 거절', () => {
  const original = writeZip(emptyZip(), { 'a.txt': 'x' });
  const flagsAt = original.readUInt32LE(original.length - 22 + 16) + 8;
  original.writeUInt16LE(original.readUInt16LE(flagsAt) | 1, flagsAt);
  assert.throws(() => writeZip(original, { 'b.txt': 'y' }), /암호/);
});
```
